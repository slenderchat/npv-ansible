# npv-ansible

[English](README.md) | **Русский**

Конфигурация Ansible для хостов сервиса npv на Debian 13.

## Текущее состояние

Сейчас репозиторий содержит:

- статический инвентарь: [`inventory/hosts.yml`](inventory/hosts.yml) и переменные ролей в [`inventory/group_vars`](inventory/group_vars);
- роль `timezone`: [`roles/timezone`](roles/timezone);
- роль `hosts`: [`roles/hosts`](roles/hosts);
- роль `hostname`: [`roles/hostname`](roles/hostname);
- роль `dns_resolver`: [`roles/dns_resolver`](roles/dns_resolver);
- роль `locale`: [`roles/locale`](roles/locale);
- роль `chrony`: [`roles/chrony`](roles/chrony);
- роль `apt_sources`: [`roles/apt_sources`](roles/apt_sources);
- требования к коллекциям: [`collections/requirements.yml`](collections/requirements.yml).

Группы хостов:

- `ingress` — входные узлы сервиса npv.
- `egress` — выходные узлы сервиса npv.

Общие для всех хостов параметры подключения заданы в `all.vars`.

Соглашение об инвентаре: переменные подключения, например `ansible_user`, `ansible_host` и `ansible_port`, могут оставаться в `inventory/hosts.yml`. Переменные ролей для группы хранятся в `inventory/group_vars/<group_name>/<role_name>.yml`, а для отдельного хоста — в `inventory/host_vars/<inventory_hostname>/<role_name>.yml`, где имя каталога точно совпадает с именем хоста в инвентаре, например `ingress-ru-tweb-msk1-01.sl-chat.ru`.

Чтобы просмотреть инвентарь локально:

```sh
ansible-inventory -i inventory/hosts.yml --graph
```

## Коллекции

Установите нужные коллекции на управляющей машине:

```sh
ansible-galaxy collection install -r collections/requirements.yml
```

## Роли

### `timezone`

Устанавливает на управляемом хосте системный часовой пояс `Europe/Moscow` с помощью `community.general.timezone` только с параметром `name`. Аппаратные часы и NTP эта роль не настраивает.

На хостах с systemd модуль читает и задаёт часовой пояс через `timedatectl`, поэтому на управляемом хосте нужны работающий `timedatectl` и файл зоны `/usr/share/zoneinfo/Europe/Moscow` из пакета `tzdata`. `hwclock` (пакет `util-linux-extra`) нужен, только если модуль переходит на путь без systemd, потому что `timedatectl` отсутствует или не работает.

Документированное поведение модуля:

- если на хосте уже задан `Europe/Moscow`, задача не сообщает об изменениях, в том числе с `--check`;
- с `--check` другой часовой пояс отображается как изменение, а на хосте ничего не меняется;
- с `--diff`, отдельно или вместе с `--check`, модуль показывает собственные значения `name` до и после.

### `hosts`

Формирует весь `/etc/hosts` из шаблона (владелец `root:root`, права `0644`) и держит его неизменяемым (`chattr +i`) между запусками. Любые строки, добавленные вне шаблона, например провайдером, удаляются. Системное имя хоста, настройки DNS-резолвера и cloud-init эта роль не настраивает.

Управляемые записи:

- `127.0.0.1 localhost`;
- `127.0.1.1 <short-name> <fqdn>`, где `<fqdn>` — это `inventory_hostname`, а `<short-name>` — его первая метка; текущее системное имя хоста, сетевые факты и DNS не используются;
- стандартные для Debian записи IPv6: `::1 localhost ip6-localhost ip6-loopback`, `ff02::1 ip6-allnodes`, `ff02::2 ip6-allrouters`;
- необязательные записи из `hosts_extra_records` (по умолчанию `[]`), которые выводятся после стандартных в заданном порядке:

  ```yaml
  hosts_extra_records:
    - address: 192.0.2.10
      names:
        - example-01.example.org
        - example-01
  ```

Поведение:

- `/etc/hosts` должен отсутствовать или быть обычным файлом; при любом другом типе, например символьной ссылке, роль завершается ошибкой до любых изменений. Для существующего файла роль читает флаги через `lsattr` при каждом запуске, в том числе на уже сведённом хосте; сведённый запуск не сообщает об изменениях и не выполняет ни перезаписи, ни `chattr`.
- Если нужно обновление, роль временно снимает `i`, если он установлен. Изменения содержимого выполняются атомарной заменой; владелец, группа и права исправляются без замены файла. Если не хватает только `i`, он устанавливается без перезаписи файла.
- После установки `i` роль повторно читает флаги и завершается ошибкой, если `i` нет. Если обновление не удалось после снятия `i`, роль пытается вернуть `i` и сообщает исходную ошибку вместе с результатом проверки.

На управляемом хосте нужны `lsattr` и `chattr` (пакет `e2fsprogs`) и файловая система с поддержкой атрибута immutable. Пока установлен `i`, обычная запись в `/etc/hosts`, в том числе со стороны cloud-init или агентов провайдера, заблокирована.

Проверка и diff:

- с `--check` роль проверяет текущее состояние и прогнозирует изменения, не изменяя `/etc/hosts` и его атрибуты;
- с `--diff` расхождение содержимого даёт один diff содержимого до и после; изменение только атрибута не даёт diff содержимого.

### `hostname`

Задаёт системное имя хоста с помощью `ansible.builtin.hostname` со стратегией `systemd`, которая через `hostnamectl` устанавливает статическое и временное (transient) имя хоста.

Имя хоста — это первая метка FQDN из инвентаря, `inventory_hostname_short`; например, `ingress-ru-tweb-msk1-01.sl-chat.ru` получает имя `ingress-ru-tweb-msk1-01`. Файлом `/etc/hosts` управляет роль `hosts`, а не эта роль.

Режимы проверки и diff поддерживаются модулем нативно: с `--check` другое имя хоста отображается как изменение без изменения хоста, а с `--diff` модуль показывает имя хоста до и после.

### `dns_resolver`

Направляет разрешение имён приложений через локальный stub systemd-resolved на `127.0.0.53`. Публичный DNS уходит только на DNS-over-TLS-серверы группы хоста. networkd, netplan, cloud-init и состояние интерфейсов роль не меняет.

Серверы задаются упорядоченным списком в обязательной групповой переменной `dns_resolver_upstreams`. Каждый элемент записывается в синтаксисе systemd-resolved: `IPv4:порт#tls-имя`. Порт 53 запрещён: systemd-resolved хранит и 53, и 853 как порт 0, а при строгом DNS-over-TLS это означает 853. Значения по умолчанию нет: если список не задан или записан неверно, роль завершается ошибкой до любых изменений. Значения заданы в `inventory/group_vars/ingress/dns_resolver.yml` и `inventory/group_vars/egress/dns_resolver.yml`:

| Группа | `dns_resolver_upstreams` |
| --- | --- |
| `ingress` | `77.88.8.88:853#safe.dot.dns.yandex.net`, `77.88.8.2:853#safe.dot.dns.yandex.net`, `185.191.32.7:853#public.sdns.bi.zone`, `185.191.32.8:853#public.sdns.bi.zone` |
| `egress` | `9.9.9.9:853#dns.quad9.net`, `149.112.112.112:853#dns.quad9.net`, `1.1.1.2:853#security.cloudflare-dns.com`, `1.0.0.2:853#security.cloudflare-dns.com` |

Drop-in `/etc/systemd/resolved.conf.d/50-dns_resolver.conf` сбрасывает унаследованные списки `DNS=` и `Domains=` и задаёт `DNS=<весь список>`, `Domains=~.`, `DNSOverTLS=yes`, `DNSStubListener=yes`, `LLMNR=no` и пустой `FallbackDNS=`. Между серверами списка systemd-resolved переключается сам и не возвращается к первому сразу. Шифрование и проверка сертификата строгие: отката на открытый DNS нет. DNS-серверы, полученные по DHCP, могут оставаться на интерфейсе; пока действует глобальный `~.`, они не используются.

`/etc/resolv.conf` становится обычным файлом `root:root` с правами `0644` и флагом immutable (`chattr +i`). В нём только `nameserver 127.0.0.53`, `options edns0 trust-ad` и `search .`. Прежний файл, символьная ссылка или отсутствующий путь заменяются.

Порядок обычного запуска:

1. Если нет `e2fsprogs` (`lsattr`, `chattr`), сначала установить его, пока работает исходный резолвер; состояние резолвера при этом не меняется. Затем записать исходное состояние: тип `/etc/resolv.conf` (обычный файл, символьная ссылка или отсутствует; любой другой тип — ошибка), его флаг `i` (ошибка `lsattr` останавливает запуск; флаг никогда не считается снятым по умолчанию), содержимое (в том числе через ссылку), drop-in с владельцем, группой и правами, состояние пакетов, а также запущен ли и включён ли systemd-resolved.
2. Установить остальные недостающие пакеты (`systemd-resolved`, `bind9-dnsutils`, `ca-certificates`, без рекомендуемых), пока работает исходный резолвер. При первой установке пакет Debian может заменить незащищённый `/etc/resolv.conf` ссылкой на stub и запустить сервис; после установки путь проверяется заново.
3. Записать drop-in. Если он изменился, перезапустить systemd-resolved; затем убедиться, что сервис включён и запущен. Неизменённый работающий сервис не перезапускается.
4. Прочитать действующие настройки через D-Bus (`busctl`) и завершиться ошибкой с конфликтующим значением и подсказкой, где искать, если публичные запросы могут уйти мимо утверждённого списка. Серверы сравниваются по адресу, порту и TLS-имени в порядке инвентаря; сохранённый порт 0 считается за 853, потому что на том же шаге проверяется `DNSOverTLS=yes`, а любой другой неожиданный порт — расхождение. Например: более поздний drop-in меняет `DNS=`, глобальные домены не равны ровно `~.`, у сетевого интерфейса есть свой DNS-домен, текущий сервер не из списка, `FallbackDNS=` не пуст, либо `DNSOverTLS`, `LLMNR` или `DNSStubListener` отличаются. Если текущим стал любой утверждённый запасной сервер, это не ошибка.
5. Запросить `deb.debian.org.` (тип A) через `dig` напрямую у `127.0.0.53` с ограниченным числом повторов. Если запуск что-то меняет или исправляет, кэш systemd-resolved сначала сбрасывается. На уже сведённом хосте кэш не трогается, поэтому ответ может прийти из кэша. Успех подтверждает настроенный путь разрешения, а не ответ каждого из серверов.
6. Только после этого атомарно заменить `/etc/resolv.conf`, установить `i` и перечитать флаги. Обычный файл заменяется модулем template. В символьную ссылку, в том числе висячую или такую, цель которой уже содержит нужный текст, запись никогда не идёт: полный файл готовится как `/etc/.resolv.conf.dns_resolver.tmp` с `root:root 0644` и переименовывается поверх ссылки; при ошибке промежуточный файл удаляется. На уже сведённом хосте ничего не перезаписывается, `chattr` не выполняется и сервисы не перезапускаются.

Если любой шаг после первого завершился ошибкой, роль восстанавливает то, что отличается от записанного состояния, и затем завершается с исходной ошибкой и результатом каждого шага восстановления:

- drop-in (или удаляет его, если его не было);
- состояние сервиса: перезапуск с восстановленной конфигурацией, если он работал, или остановка, если не работал; для юнита, существовавшего до запуска, также возвращается состояние `enabled` или `disabled`, если запуск его изменил, а другие состояния, например `masked`, не меняются, и ничего не размаскируется. Юнит, установленный этим запуском, остаётся установленным и включённым, и отчёт об этом сообщает;
- исходный обычный файл с владельцем, правами и флагом `i` (замена ссылки идёт тем же переименованием подготовленного файла), исходная ссылка или отсутствие файла.

Каждый восстановленный элемент перечитывается, и восстановленным называется только проверенный результат.

Если исходная ссылка больше не ведёт к исходному содержимому (например, её цель принадлежала резолверу, который удалила установка пакета, или это файл systemd-resolved при остановленном сервисе), сохранённое содержимое заменяет ссылку обычным файлом через то же переименование подготовленного файла, и роль сообщает об этом. После восстановления роль один раз проверяет разрешение имён через NSS (`getent`). Пакеты никогда не удаляются.

Проверка и diff:

- с `--check` роль читает текущее состояние и прогнозирует установку пакетов, каталог и файл drop-in, перезапуск или запуск сервиса, замену ссылки обычным файлом и флаг `i`. Без `lsattr` прогнозируется установка необходимого пакета, а текущий флаг `i` обычного `/etc/resolv.conf` сообщается как неизвестный; только из-за этого запуск не завершается ошибкой. Роль не запускает сервисы, не сбрасывает кэш и не отправляет DNS-запросы, а проверку во время выполнения помечает как отложенную. На хосте без пакета установка и запуск показываются сообщениями, потому что apt не может обновить списки пакетов, а юнита ещё нет.
- с `--diff` для drop-in и `/etc/resolv.conf` показывается по одному diff содержимого; для ссылки «до» — это содержимое её цели, для висячей ссылки — пустое содержимое.

### `locale`

Задаёт постоянную системную локаль по умолчанию `LANG=C.UTF-8` в `/etc/locale.conf` одной задачей `ansible.builtin.lineinfile`. Если файла нет, он создаётся; владелец и права поддерживаются как `root:root 0644`. Существующая активная строка `LANG=`, в кавычках или без, заменяется; `LANGUAGE`, `LC_*` и закомментированные строки, а также другие настройки и комментарии сохраняются. Генерация локалей и уже запущенные сессии этой ролью не затрагиваются.

Режимы проверки и diff поддерживаются модулем нативно: с `--check` отсутствующий или другой `LANG` отображается как изменение без изменения хоста, а с `--diff` модуль показывает содержимое файла до и после.

### `chrony`

Обеспечивает установку пакета `chrony` и включение и запуск `chrony.service` модулями `ansible.builtin.apt` и `ansible.builtin.systemd_service`. Конфигурация пакета и источники времени сохраняются; повторный запуск не сообщает об изменениях и не перезапускает сервис. Работающий демон сам по себе не подтверждает синхронизацию часов.

С `--check` роль читает только локальные метаданные APT и не обновляет их: если chrony уже установлен или в них есть кандидат на установку, apt моделирует установку и с `--diff` показывает транзакцию пакетов; иначе установка отображается как изменение, транзакция которого неизвестна, пока метаданные APT недоступны. Если `chrony.service` ещё нет, запланированный запуск показывается сообщением; существующий юнит оценивается модулем.

### `apt_sources`

Управляет источниками APT Debian в `/etc/apt/sources.list.d/debian.sources` (deb822, `root:root 0644`): `https://deb.debian.org/debian` для `trixie` и `trixie-updates` и `https://security.debian.org/debian-security` для `trixie-security`, с `Types: deb` и `Signed-By: /usr/share/keyrings/debian-archive-keyring.pgp` в каждой записи. До любых изменений связка ключей и набор сертификатов `/etc/ssl/certs/ca-certificates.crt` должны быть доступны для чтения; ключи никогда не загружаются. Роль не устанавливает, не обновляет и не удаляет пакеты и не задаёт ни `APT::Default-Release`, ни записи `deb-src`.

Переменные (по умолчанию `main` и без backports):

- `apt_sources_components` — полный упорядоченный список компонентов, уникальные значения из `main`, `contrib`, `non-free` и `non-free-firmware`;
- `apt_sources_backports_packages` — точные имена бинарных пакетов, разрешённых из `trixie-backports`; пустой список отключает backports.

Переопределения задаются в `inventory/group_vars/<group_name>/apt_sources.yml` или `inventory/host_vars/<inventory_hostname>/apt_sources.yml`. Пример файла хоста:

```yaml
apt_sources_components:
  - main
  - non-free-firmware
apt_sources_backports_packages:
  - example-package
```

При непустом списке роль добавляет запись `trixie-backports` и `/etc/apt/preferences.d/npv-backports.pref`, который даёт перечисленным пакетам приоритет 100, а всем остальным пакетам backports — приоритет -1, поэтому обычным источником остаётся stable везде, где в нём есть пакет. Добавление пакета в список ничего не устанавливает и не обновляет. Предполагаемый порядок работы — явный выбор, `apt install <package>/trixie-backports`; зависимость, которой нужна версия из backports, тоже должна быть в списке. Это соглашение, а не гарантия APT: пакет из списка без кандидата в stable устанавливается из backports обычной командой `apt install`. Файл предпочтений записывается до включения источника и удаляется только после его отключения.

Миграция. До любых изменений роль читает `/etc/apt/sources.list`, активные файлы `.list` и `.sources` и предпочтения APT, не обращаясь к зеркалам. Распознаются только простые записи `deb`/`deb-src` для `/debian` на `deb.debian.org`, `ftp.debian.org` или `ftp.<cc>.debian.org` и для `security.debian.org/debian-security` с перечисленными выше выпусками trixie, компонентами Debian и не более чем `signed-by` со связкой ключей Debian. Файл только с такими записями, активными или отключёнными, мигрируется: в `/etc/apt/sources.list` остаётся комментарий, другой файл удаляется, официальные записи `deb-src` отбрасываются. Другие репозитории и предпочтения не затрагиваются. Роль останавливается до любых изменений, называя файл и причину, если перезаписываемый или удаляемый файл, включая существующий `debian.sources`, содержит также другие записи или отключённые записи deb822 других репозиториев, у официальной записи другой выпуск или дополнительные параметры, backports берётся из другого архива, `npv-backports.pref` записан не ролью или маркер незавершённого обновления не является собственным обычным файлом роли. При включённых backports запись предпочтений сохраняется, только если она заведомо не может совпасть с `trixie-backports`: закрепление `origin` для узла, отличного от `deb.debian.org`, или закрепление `release` с буквальным значением `n`, отличным от `trixie-backports`, или буквальным значением `o` или `l`, отличным от `Debian Backports`. Значение выпуска (`a=`) никогда не считается доказательством, поскольку псевдонимы выпусков переходят между релизами. Любая другая запись, например закрепление `version`, останавливает роль с указанием файла и строки; полный язык политик APT роль не вычисляет. При отключённых backports другие предпочтения не проверяются. Другие схемы, включая зеркала провайдеров и URI `mirror+file:`, автоматически не мигрируются.

Удаление компонента, сужение или отключение backports проверяется по установленным пакетам в локальном кэше APT (`dpkg-query`, `apt-cache policy`). Для каждого установленного пакета, версия которого есть в удаляемом источнике или теряет допуск backports, и для каждой установленной версии, известной только из статуса dpkg, оставшийся источник должен предлагать установленную или более новую версию (сравнение `dpkg --compare-versions` на хосте) с приоритетом не ниже 100 после изменения. Версии backports оцениваются с предлагаемым ограничением; остальные приоритеты берутся из текущего `apt-cache policy` и существующих предпочтений, которые роль сохраняет. Роль останавливается до любых изменений с причиной для каждого пакета: недоступен (версию предлагает только удаляемый источник), запрещён (оставшееся предложение ниже приоритета 100), происхождение неясно (версия из статуса dpkg без оставшегося предложения; роль не утверждает, откуда она взялась) или не определено (существующие предпочтения или неоднозначная запись `apt-cache policy` не позволяют определить результат). Она также останавливается, если нет индекса удаляемого источника. Эти проверки выполняются только при удалении компонента или сужении допуска backports; иначе индексы не нужны.

После изменения источников обычный запуск обновляет индексы командой `apt-get update` с `APT::Update::Error-Mode=any`, поэтому частичный сбой завершает запуск ошибкой. `/var/lib/apt/npv-apt-sources.refresh-pending` создаётся до изменения и удаляется после успешного обновления; пока он существует, следующий запуск повторяет обновление. Повторный запуск без изменений ничего не меняет и индексы не обновляет.

Проверка и diff:

- с `--check` роль выполняет ту же проверку только для чтения и останавливается на тех же препятствиях; она перечисляет мигрируемые файлы, показывает удаления и необходимость обновления индексов и ничего не записывает, не обновляет и не обращается к зеркалам. Файл, каталога которого ещё нет, показывается сообщением;
- с `--diff` `debian.sources`, файл предпочтений и сокращённый `/etc/apt/sources.list` показывают разницу содержимого; для удаляемых файлов показывается состояние пути.

## Планируемые плейбуки

Ни один из этих плейбуков пока не существует:

- `new_server.yml` — базовая настройка ОС на всех управляемых хостах.
- Отдельный плейбук для ingress-узлов (имя пока не выбрано).
- Отдельный плейбук для egress-узлов (имя пока не выбрано).

## Секреты

Секреты хранятся в Ansible Vault и никогда не коммитятся в открытом виде.
